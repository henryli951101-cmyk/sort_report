# 排序演算法效能分析報告 (Sorting Algorithms Analysis)

## 📌 前言
本報告旨在透過實作五種經典排序演算法，觀察並記錄各演算法在處理不同資料規模（$n$）時的執行時間。透過實驗數據與理論複雜度的對照，分析演算法在效能上的差異。

---

## 📖 排序法原理介紹

### 1. 🫧 氣泡排序 (Bubble Sort)
* **原理**：重複走訪數列，每次比較相鄰的兩個元素，若順序錯誤則交換。每一輪結束後，最大值會像氣泡一樣「浮」到序列末端。
* **特點**：邏輯最簡單，但大量資料時效能極差。

### 2. 🎯 選擇排序 (Selection Sort)
* **原理**：在未排序部分尋找最小值，並將其與未排序部分的第 1 個元素交換位置。
* **特點**：交換次數少，但無論資料狀態如何，時間複雜度皆固定。

### 3. 🃏 插入排序 (Insertion Sort)
* **原理**：將資料分為已排序與未排序兩部分，每次從未排序中取出一筆，插入到已排序部分中的正確位置。
* **特點**：在資料幾乎排好序的情況下，效能極高。

### 4. ✂️ 合併排序 (Merge Sort)
* **原理**：採用「分而治之」策略。將陣列對半切開直到成為單一元素，再將其兩兩有序合併回完整的陣列。
* **特點**：效能極度穩定，但需要額外空間儲存暫存陣列。

### 5. ⚡ 快速排序 (Quick Sort)
* **原理**：選定一基準值 (Pivot)，將小於基準的移到左邊，大於基準的移到右邊，再對左右兩邊遞迴排序。
* **特點**：平均速度最快，是目前實務上最常用的排序演算法。

---

## 📊 複雜度分析比較

| 演算法 | 平均時間複雜度 | 最差時間複雜度 | 空間複雜度 | 穩定性 |
| :--- | :--- | :--- | :--- | :--- |
| **Bubble Sort** | $O(n^2)$ | $O(n^2)$ | $O(1)$ | 穩定 |
| **Selection Sort** | $O(n^2)$ | $O(n^2)$ | $O(1)$ | 不穩定 |
| **Insertion Sort** | $O(n^2)$ | $O(n^2)$ | $O(1)$ | 穩定 |
| **Merge Sort** | $O(n \log n)$ | $O(n \log n)$ | $O(n)$ | 穩定 |
| **Quick Sort** | $O(n \log n)$ | $O(n^2)$ | $O(\log n)$ | 不穩定 |

## 🧪 實驗設計與結果呈現

### 實驗設計
* **測試環境**：Web Browser (JavaScript) / C Runtime
* **數據來源**：隨機產生範圍 0-1000 之整數陣列
* **測量指標**：執行時間 (ms)

### 實驗結果 (範例數據)
| 演算法 \ 資料量 | $n=100$ | $n=1000$ | $n=5000$ | $n=10000$ |

## 💡 心得與結論

### 1. 演算法效能差異
從實驗數據可以明顯觀察到，$O(n^2)$ 家族（氣泡、選擇、插入）在資料量 $n$ 超過 5000 之後，執行時間呈現指數級成長。而 $O(n \log n)$ 家族（快速、合併）即使在資料量翻倍的情況下，依然保持極速。

### 2. 適合場景分析
* **Bubble Sort**：適合教學與極小規模數據。
* **Insertion Sort**：適合資料已經「接近排序完成」的場景。
* **Quick Sort**：大多數實務開發的首選，雖然最差情況會退化，但在隨機數據下表現最優。

### 3. 學習體會
以前在書本上看複雜度 $O(n^2)$ 只是一個概念，但透過這次動手寫程式並記錄時間，才發現資料量一大，差一個次方就是「毫秒」與「秒」甚至是「分鐘」的區別。這讓我理解到選擇正確演算法在軟體開發中的重要性。
