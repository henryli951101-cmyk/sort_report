排序演算法效能分析報告 (Sorting Algorithms Analysis)📌 前言本研究旨在透過實作五種經典排序演算法（Bubble, Selection, Insertion, Merge, Quick Sort），觀察並比較各演算法在處理不同資料規模（$n$）時的效能差異。透過理論分析與實際數據模擬，驗證時間複雜度對於程式執行效率的影響。📖 排序法原理介紹1. 氣泡排序 (Bubble Sort)原理：重複走訪要排序的數列，一次比較兩個元素，如果他們的順序錯誤就把他們交換過來。走訪數列的工作是重複地進行直到沒有再需要交換。操作：相鄰元素兩兩比較，每一輪會將最大值「浮」到數列末端。2. 選擇排序 (Selection Sort)原理：在未排序序列中找到最小（大）元素，存放到排序序列的起始位置，然後從剩餘未排序元素中繼續尋找。操作：掃描全場找到最小值，與當前輪次的第一個位置交換。3. 插入排序 (Insertion Sort)原理：構建有序序列，對於未排序數據，在已排序序列中從後向前掃描，找到相應位置並插入。操作：類似整理撲克牌，將一張新牌插入到左手已排好序的正確位置。4. 合併排序 (Merge Sort)原理：採用「分而治之」(Divide and Conquer) 策略。將陣列對半切開直到成為單個元素，再將其兩兩有序合併。操作：遞迴分割與有序合併，需要額外的記憶體空間。5. 快速排序 (Quick Sort)原理：挑選一個基準值 (Pivot)，將數列分為比基準小與比基準大的兩部分，再對這兩部分遞迴排序。操作：分區 (Partitioning) 處理，實務上在平均狀況下擁有極佳的效能。📊 複雜度分析比較表演算法平均時間複雜度最差時間複雜度空間複雜度穩定性Bubble Sort$O(n^2)$$O(n^2)$$O(1)$穩定Selection Sort$O(n^2)$$O(n^2)$$O(1)$不穩定Insertion Sort$O(n^2)$$O(n^2)$$O(1)$穩定Merge Sort$O(n \log n)$$O(n \log n)$$O(n)$穩定Quick Sort$O(n \log n)$$O(n^2)$$O(\log n)$不穩定🧪 實驗設計與數據模擬實驗環境實作語言：JavaScript / C (根據最終實作調整)測試環境：Chrome Browser / Local Compiler測試資料：使用隨機產生的整數陣列（Range: 0-1000）實驗規模觀察資料量 $n = 100, 500, 1000, 5000$ 時的執行時間（單位：ms）。📈 結果呈現與比較注意：以下數據為模擬趨勢，建議填入你實際執行程式後得到的數據。演算法 \ 資料量n=100n=500n=1000n=5000Bubble Sort0.2ms3.5ms12.1ms280msSelection Sort0.1ms2.1ms8.5ms150msInsertion Sort0.1ms1.8ms6.2ms110msMerge Sort0.05ms0.2ms0.5ms2.5msQuick Sort0.03ms0.15ms0.4ms2.1ms效能分析觀察$O(n^2)$ 家族：在 $n$ 較小時差距不大，但當 $n$ 增加 10 倍時，時間增加約 100 倍，符合理論預期。$O(n \log n)$ 家族：不論資料量如何增加，執行速度皆維持在極低水位，表現遠優於初階排序法。💡 心得與結論透過本次實驗，我深刻體會到「演算法效率」在處理大量數據時的關鍵影響。雖然 Bubble Sort 的邏輯最直觀易懂，但在面對數千筆資料時就顯得力不從心。個人觀察重點：插入排序在小資料量或幾乎排好序的情況下，表現甚至優於進階排序。快速排序雖然最差情況會退化，但在隨機數測試中始終維持最高效率。在開發網頁或軟體時，應優先考慮系統內建的排序函式（通常基於 Quick/Merge Sort），以確保在極端狀況下的穩定性。
